# 从近年顶会全文到 idea

## 检索边界

把用户领域拆成任务、关键机制、数据/场景、限制条件；先按任务与问题搜索，再扩展技术词。记录检索执行日和最近 24/36 个月的精确起止日期，以及所覆盖会议届次。会议的论文年度与预印本首次上线时间分开记录。

会议范围随领域确定，例如通用 ML 的 ICML/NeurIPS/ICLR，视觉的 CVPR/ICCV/ECCV，语言的 ACL/EMNLP 等；此处是范围示例，不是固定排名。优先目标领域主会录用论文；官方录用页、论文集、OpenReview 决定页用于核验。DBLP等索引可补充元数据，arXiv用于全文与前沿补充，不能仅凭标题或摘要认定已录用。

分三类资料：

- 核心基础：时间窗内、领域相关、录用状态核实的目标主会论文。
- 前沿/背景补充：预印本、workshop、必要的较早奠基工作，保留各自标签。
- 技术报告：同领域或在图示结构、任务呈现上相近的报告，记录用途；不能混入“顶会主会论文数量”。

默认先筛约 15—30 个候选，选择约 6—10 篇全文精读，按资料量、覆盖情况和用户预算调整；这是工作量起点，不是完成门槛或搜索上限。不要为了凑数纳入不相关论文。核心资料不足时明确记录缺口，继续可行的来源扩展。

## 使用 paper-search

已安装 `paper-search` skill 时先读取其 `SKILL.md` 及当前所需的 CLI 参考，检查 `command -v paper-search`、`paper-search --help`；需要直达工具时读取 `paper-search tools --pretty` 的实际参数。环境不确定时按该 skill 运行脱敏自检。未安装时按 [skill-routing.md](skill-routing.md) 使用实际可用的检索与全文能力，保留同样的证据字段。

流程：metadata search → 核验身份/年份/录用 → 去重 → 下载 → PDF 内容确认 → 阅读与图示查看。本工作流明确包含 PDF 下载，核验后即可下载，不再为每篇重复请求确认。

典型命令以实际 CLI 为准：

```bash
paper-search search 'task mechanism keywords' --sources dblp,openreview,arxiv --max-results 20 --pretty
paper-search tools --pretty
```

下载优先论文集、作者仓库和开放全文来源。需要 fallback 时，用核验元数据调用 `download_with_fallback`，保存到项目资料目录；可传 `useSciHub:false` 将本流程限制为公开/已获访问权来源。不要添加不存在的参数，不修改全局下载配置。

用已知 DOI/arXiv ID 做引用扩展时，调用 `get_paper_references` 或 `get_paper_citations`，不要把关键词搜索当引用网络。CLI不可用时指出具体能力缺口，可先从官方来源完成同等核验与公开PDF获取，并记录 fallback；不要将工具未运行说成运行成功。

## 文献登记和下载完成的含义

在 `literature/manifest.csv` 或同等结构中记录：

`paper_id, title, authors, venue, year, track, acceptance_status, official_url, doi_or_arxiv, pdf_url, local_pdf, version, download_status, read_status, role, failure_reason`。

下载成功要核实文件可读且确为目标论文，避免登录页/HTML伪装PDF。失败项逐条记录，继续其余项；保留已有文件，不用同名新版本覆盖已读版本。可以使用当前PDF能力或必要时的 `nature-paper-card`，提取方法、正文和图表。

只有摘要时，不对未见的实验细节或美术风格作结论；PDF仅下载未读时，状态仍为未读。已有合格文献库可复用，按缺口补查，不从零重复下载。

## 同一套论文同时积累三类材料

在 `literature/evidence-matrix.md` 中逐篇写：

| 字段 | 要求 |
|---|---|
| 研究问题、已有假设与限制 | 绑定页码/章节；区分作者陈述与自己的推断 |
| 核心洞见与具体机制 | 写明它怎样改变方法，不只记模型名 |
| 动机分析 | 找到“为什么这样设计”的证据及其在论文中的位置；不存在则记录未见 |
| 性能、消融、反直觉/通用证据 | 分别记录，保留比较条件与限制 |
| 可继续探索的问题 | 标明文献明确提出/跨论文推断/本次假设 |
| 叙事借鉴 | 段落角色、动机到方法的过渡，保留定位 |
| 视觉借鉴 | PDF页码、图号、图类型、截图路径；标明已看/待看 |

这样后续 brainstorm、storyline 和绘图都回到同一组实际材料，而不是分别依靠记忆。

## 文献驱动 brainstorm

读完用于支撑候选的核心全文后，从这些关系产生 idea：不同论文对同一问题的不同解释、在固定条件下成立但尚未展开的假设、新方法与未充分探索任务的结合、观察与现有设计之间的差异、可跨任务复用的机制。

每个候选写入 `ideas.md`：

1. 原始操作性 idea：准备改变什么、解决什么任务。
2. 来源：至少列实际支持它的论文定位；推断明确标记。
3. 最近相近工作及仍需查证的差异，不把“检索没找到”写成“此前无人做”。
4. 为什么此时可做：近年发展、尚未展开的问题和已有研究积累。
5. 最小机制、可用数据/代码/算力、首个动机实验。
6. 与其他候选的差别；选择一条主线的理由。

候选数按发现而定，通常先给 3—5 条可区分路线；这是 brainstorming 选项数，**不等于一篇论文必须有三个创新点**。已有用户指定 idea 时直接用文献补足它，保留原机制；新机制作为可选变体。若无需用户做关键取舍，可以推荐一条主线继续进行低成本的 insight 和实验设计，不自动启动大规模训练。

输出时保留证据边界。核心全文仍缺失时可交付问题清单、待查关系和暂定候选，但“文献驱动 idea 已完成”的状态保持未完成。
