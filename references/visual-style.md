# 从实际参考图到论文美术风格

## 参考来自前面的文献工作

优先复用 `literature/evidence-matrix.md` 中已经下载和阅读的论文。按图的论述作用选参考：方法总览、动机分析、特征可视化、主要结果或多任务展示。补充同领域或在结构上相近的技术报告，明确相似之处，记录正式来源与版本。

开始阶段就记录可能的图示参考；**正式视觉打磨在科学内容和主要论述明确之后进行**。没有结果时可以先做有明确假设标签的方法示意，不能画成已经发生的实验结果。

仅有文件名/摘要/文献标题不等于看过图。用PDF渲染或文档/浏览器能力打开实际页面，查看需要借鉴的图，保存页码、图号和本地截图或裁剪路径。现有参考图足够时不额外搜索。

## 先提取，再综合

在 `figures/style-sources.md` 记录每个参考：

`source_id、论文/技术报告与版本、正式URL、本地PDF、页码/图号、截图路径、已查看状态、参考角色（内容/风格/结构/输入资产）、可借鉴项`。

逐图提取，不先给所有图套一个默认“顶会配色”：

| 参数 | 记录方式 |
|---|---|
| 配色与语义 | 从图中取样的颜色/可测值、对应角色；估计值明确标记 |
| 字体层级 | 标题、模块、正文、注释的字体和尺度；不能确认字体名时标记近似 |
| 形状与线条 | 圆角、描边宽度、虚线和容器样式 |
| 版面节奏 | 面板排列、主要方向、留白、密度、间距 |
| 箭头语义 | 数据/控制/反馈/训练专用关系的视觉区分 |
| 图例与贡献突出 | 旧组件、新组件和输出如何区分 |

将结果综合成 `visual-spec.md`：选择主要参考的构图与层级，用另一参考补充合适的图例或颜色语言；参数冲突时选择并说明依据，不机械拼贴。每个采用的参数或布局规则都能回到参考图或一个标明理由的适配决定。

如果参考图未打开，风格状态保持“待提取”；可以交付独立草图，不能声称它已经模仿了那些论文。

## 将风格交给 academic-figures-drawer

已安装该 skill 时，在创建框架/模块图前读取它的 `SKILL.md`、`references/style-extraction.md` 和当前图型需要的参考；未安装时使用 [skill-routing.md](skill-routing.md) 的替代能力，不虚构该 skill 的调用。以下流程适用于实际使用 academic-figures-drawer 的情况。传入：

- 已稳定的任务、输入输出、方法阶段、模块机制与术语；
- 动机图/框架图/模块图等各自的论述任务；
- 原始参考截图、style-sources和visual-spec；
- 已知/未知维度、训练推理区别、已有与新增组件；
- 图的目标论文宽度、语言和可编辑交付要求。

按其流程建立 brief、必要的布局与资产记录，先检查语义再写XML。`.drawio` 是框架和模块图的源文件；导出的SVG/PDF/PNG是派生物。每种形状、颜色、连线都对应本方法的实际意义，不因为参考图有token格子就给不含token的模型加格子。

先运行该 skill 的 `validate_visual_quality.py` 和 `validate_drawio.py`，检查实际导出图；按其规定完成目标论文尺寸下的截图检查和修订。camera-ready或关键交付按其至少三轮视觉验证执行，保留截图与defect-log。工具受限时报告实际交付与未完成的导出，不把XML通过当作视觉检查通过。

仅当用户要求精确复刻既有图时，加载它的 reference-replication-protocol；借鉴风格不等于复制参考论文的科学内容。

## 数据图、表与任务展示

折线图、性能表、热图等使用真实数据及绘图工具；可调用 `ccf-visual-composer` 复用视觉规格。保留原文要求：领先项根据真实结果加粗，非领先项显眼解释；模型内部可视化和分析图用于说明动机。

原文“方法名称与任务结合”的技巧可以用在封面示例或任务展示：生成与方法名称有关的输入图像，再通过真实方法得到深度/法线等输出。生成的视觉资产只属于输入/情境，任务结果需要实际方法产生；没有运行时明确标为待运行或概念示意。不要把生图工具生成的深度图冒充模型结果。

生成式工具仅用于非语义构图探索或输入/情境资产；方法框架保持可编辑向量语义，数字结果仍来自实验。需要生图时使用当前图像生成能力并记录资产角色。

## 视觉交付

交付实际参考图记录、提取出的风格规格、编辑源文件、最新预览/导出、静态与视觉检查状态。说明仍有哪些近似或缺失。向论文写作环节回传图意、图注事实及首次引用位置，使图与动机、方法和证据连起来。
